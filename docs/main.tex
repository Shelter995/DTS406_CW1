\section{Individual Literature Reviews}
\subsection{Review 1: Zijie Xue}
I believe that document topic classification is a method to reduce manual reading. Users do not need to open each document one by one to read the text content for screening; they only need to look for it under the corresponding topic label. The core task of automatic text classification is to categorize a small amount of text content into the appropriate topic label \cite{sebastiani2002}. In practice, this technology can be applied to categorizing news articles into different sections of news websites, distributing work orders to different teams in customer service platforms, or grouping movies by type on movie websites.

The user value is obvious, but the task itself is not simple. Take our experiment as an example. Movie genres often overlap. A movie can be a crime, thriller, and horror film. And the number of examples for some labels is much larger than others, so the model may exhibit higher confidence when dealing with large categories like drama film. The two datasets in this experiment also bring another issue: the IMDb dataset is more like brief advertisements, while the plot descriptions on Wikipedia are more like complete plot overviews.

Therefore, I think simple baseline models are still important. Through TF-IDF features, we can know which words are useful \cite{ramos2003}. Naive Bayes has a fast calculation speed, but it must ensure the independence assumption of features; SVM is a powerful baseline model for text classification \cite{joachims1998}. TextCNN can learn phrase information from embedding vectors through neural network models \cite{kim2014cnn}, but it cannot capture long-range global dependencies. The MLP model combined with TFIDF features can model global interactions, but it cannot care about the order of words.

\subsection{Review 2: Fengyuan Shu}
The key to document topic classification lies in how the original text is converted into weight values or vectors. TF-IDF assigns higher weights to words that are important in a particular document but rare across all documents \cite{ramos2003}. Therefore, it is still widely used in tasks such as paper indexing, legal document retrieval, and comment classification. In movie plot analysis, words like "haunted", "spaceship", or "cowboy" can serve as strong genre characteristic signals.

But feature design will bring some risks. Sparse word features do not know that different words may have related meanings. Long Wikipedia plots may include many names, places, and side events that are not useful for genre prediction. And compound labels which means one source label may contain several possible target labels will make the problem more complicated.

In this experiment, the four algorithms having their own characteristics give a comparison. Naive Bayes is simple, but it strongly depends on independence assumption. SVM usually perform well for high-dimensional sparse text \cite{cortes1995svm,joachims1998}. TextCNN moves away from pure TF-IDF by using embeddings and convolution filters to detect short local patterns \cite{kim2014cnn}. TF-IDF MLP keeps the engineered TF-IDF input but adds a neural classifier, so it can learn non-linear combinations.

\subsection{Review 3: Junyu Zhou}
In this experiment, I did a lot of work in the evaluation aspect. A topic classifier is valuable only when its predictions are reliable across all labels, not just good on average. So, instead of accuracy rate, we pay more attention to the F1 score. This connects with the overall goal of automatic text categorisation\cite{sebastiani2002}. Similar systems are used in email filtering, content moderation, and digital library organisation. In this experiment, every plot summary is treated as one document, and the target topic is the movie genre.

This experiment also faced some challenges. If a dataset has fewer examples for some genres, a model can obtain a fair accuracy while still missing the smaller classes. Macro recall, and macro-F1 are more suitable because every genre contributes equally. These indicators also make compounding labels easier to discuss, such as action films with adventure, or thriller films with horror and crime.

The models should therefore be compared by both score and behaviour. Naive Bayes is easy to reproduce and gives a useful lower-complexity reference. SVM often becomes the strongest traditional baseline when TF-IDF keywords are clear \cite{cortes1995svm,joachims1998}. TextCNN tests whether sequence-based neural learning helps when embeddings are trained from the experiment data \cite{kim2014cnn}. TF-IDF MLP is a different neural choice: it does not read word order directly, but it can combine word-level and character-level TF-IDF features in a non-linear way. This makes the final comparison more informative than simply trying four unrelated classifiers.

\subsection{Cleaning and Label Mapping}
The original label spaces are different. IMDb has cleaner single labels, while Wikipedia contains labels such as \textit{romantic drama}, \textit{crime drama}, and many rare labels. We map both datasets into 10 shared labels, written here in the same priority order used for Wikipedia compound-genre mapping: horror, science\_fiction, thriller, adventure, action, crime, romance, comedy, western, and drama. IMDb \textit{sci-fi} is mapped to \textit{science\_fiction}. The priority order is needed because many Wikipedia labels contain more than one genre word. Earlier labels are checked first, so more distinctive or easily absorbed genres are kept before broader genres when a single final label must be chosen.

The cleaning steps are: removing empty texts, removing very short texts, removing Wikipedia citation marks, normalising spaces, lowercasing, tokenisation, stop-word removal, and lemmatisation. Two text fields are saved. \texttt{text\_clean\_tfidf} is used for TF-IDF and for final neural sequence input. \texttt{text\_clean\_dl} is kept as a lighter sequence-cleaned version, but the final report uses \texttt{text\_clean\_tfidf} because it reduces noise and improves model stability.

\section{Algorithm Design and Implementation}
\subsection{System Pipeline}
Our system is built by Python. Data cleaning scripts are located in "utils" folder. Training scripts are under "experiments" folder. We use scikit-learn \cite{sklearn_docs} for our traditional models, and PyTorc \cite{pytorch_docs} for our neural models. To ensure a fair comparison, we use the same split of training and testing data for all four models.

The system is designed to keep data preparation and actual experiments separate. The preprocessing script reads the raw IMDb text files and the Wikipedia CSV file, applies label mapping, writes two processed CSV files, and stores the split column. The analysis script then produces dataset statistics and word-frequency tables. This design makes all models read the same processed files and do not create their own train-test splits. So, the experiments can be reproducible.

\subsection{Selected Models}
Naive Bayes is a fast probabilistic baseline. The text is first converted into TF-IDF features, and the classifier estimates which words are more likely under each genre. The pseudo-code below shows feature extraction and probability-based prediction. They are both key components.

\begin{lstlisting}[style=pseudocode,caption={Naive Bayes with TF-IDF.}]
FUNCTION TrainNaiveBayes(train_texts, train_labels):
    X_train = TFIDF(train_texts)
    model = MultinomialNB(alpha=0.5)
    FIT model on X_train and train_labels
    RETURN vectorizer, model

FUNCTION PredictNaiveBayes(vectorizer, model, test_texts):
    X_test = TRANSFORM test_texts with vectorizer
    RETURN PREDICT model on X_test
\end{lstlisting}

SVM is the second traditional method. It uses TF-IDF words and bi-word features to learn a large-margin linear boundary. Since many genre cues appear in the form of keywords or phrases, this method is suitable for sparse text vectors. The key pseudo-code is shown as follows.

\begin{lstlisting}[style=pseudocode,caption={SVM with TF-IDF.}]
FUNCTION TrainSVM(train_texts, train_labels):
    X_train = TFIDF(train_texts, unigram_and_bigram=True)
    model = SVM(class_weight="balanced")
    FIT model on X_train and train_labels
    RETURN vectorizer, model

FUNCTION PredictSVM(vectorizer, model, test_texts):
    X_test = TRANSFORM test_texts with vectorizer
    RETURN PREDICT model on X_test
\end{lstlisting}

TextCNN is the first deep learning model. As the key pseudo-code shown as follows, it reads token ids, looks up word embeddings, and applies convolution filters over local word windows. And then use max-pooling to keep the strongest phrase signal for each filter. This follows the wider use of convolutional networks for text classification, including word-level CNNs and character-level CNNs \cite{kim2014cnn,zhang2015charcnn}.

\begin{lstlisting}[style=pseudocode,caption={TextCNN with word embeddings.}]
FUNCTION TrainTextCNN(train_tokens, train_labels):
    vocab = BUILD_VOCAB(train_tokens)
    input_ids = ENCODE_AND_PAD(train_tokens)
    FOR each epoch:
        embeddings = LOOKUP(input_ids)
        feature_maps = CONVOLVE embeddings with filter sizes 1,2,3,4,5
        pooled = MAX_POOL(feature_maps)
        logits = Linear(Dropout(pooled))
        UPDATE model using cross entropy loss
    RETURN model, vocab
\end{lstlisting}

TF-IDF MLP is the second deep learning model. Instead of reading token sequences, it uses word and character TF-IDF features as input to a multi-layer perceptron. This design not only keeps keyword features but also allows non-linear neural classification. The key pseudo-code is shown as follows.

\begin{lstlisting}[style=pseudocode,caption={TF-IDF MLP neural classifier.}]
FUNCTION TrainTfidfMLP(train_texts, train_labels):
    X_train = WORD_AND_CHAR_TFIDF(train_texts)
    model = MLP(input_dim, hidden_dim=1024, output_dim=num_labels)
    FOR each epoch:
        logits = model(X_train)
        UPDATE model using cross entropy loss with label smoothing
    RETURN vectorizer, model
\end{lstlisting}

\subsection{Model Strengths and Weaknesses}
Naive Bayes is fast and simple, but it must assumes words are independent. SVM is goot at sparse TF-IDF features, but it falls short in learning semantic embeddings. TextCNN can learn local phrase patterns, but it needs enough training examples and good embeddings. TF-IDF MLP uses TF-IDF features and learns non-linear combinations, but it still can not directly understand word order.

The four models we used have covered different modelling ideas. Naive Bayes is a probabilistic baseline. SVM is a strong margin-based traditional baseline. TextCNN is an embedding-based neural model that directly reads token sequences. TF-IDF MLP is a neural classifier over engineered text features. Therefore, the experiment does not only compare scores; it also compares whether keyword features, local phrase learning, or non-linear neural classification are more useful for movie genre prediction.

\subsection{Analysis}
On IMDb, SVM gives the best macro-F1 by a very small margin, while Naive Bayes gives the highest accuracy and TF-IDF MLP gives the highest macro precision. This dataset contains short summaries with strong genre words, so TF-IDF features are very useful for all three TF-IDF-based models. The differences among Naive Bayes, SVM, and TF-IDF MLP are small, which suggests that the cleaned IMDb task is mainly driven by clear keyword evidence.

On Wikipedia, TF-IDF MLP is the best model. Wikipedia plots are much longer, and many documents contain mixed events, names, and subplots. TF-IDF still works well because it can focus on important words across long documents. The MLP slightly surpasses SVM because it can learn non-linear combinations of word and character TF-IDF features. The long Wikipedia plots also contain many character names and detailed events that are not directly useful for genre classification, which limits the performence.

TextCNN performs lower than the TF-IDF-based models on both datasets. This does not mean CNN is useless for text classification. It means that in this experiment, embeddings are trained from scratch and the data size is medium. Without pretrained word vectors, the model has to learn both word meanings and classification boundaries from the same limited data. And the genres in Wikipedia such as adventure, science fiction, and western are below 1000 samples. This hurts macro-F1 because minority labels contribute equally to the final score.

The training curves in Figures~\ref{fig:training_loss} and~\ref{fig:val_f1} also explain the neural results. TextCNN keeps reducing training loss for more epochs, but the validation macro-F1 moves up and down. This means lower training loss does not always mean better generalisation. TF-IDF MLP reaches its best validation score early, so early stopping prevents it from fitting too strongly to the training split.

Naive Bayes is competitive on IMDb but weaker on Wikipedia. Its simple word-count assumption works better for short promotional summaries than for long plots. SVM is more stable because it handles many sparse features and uses a margin-based decision boundary. The confusion matrices in Figure~\ref{fig:confusion_examples} show that many errors happen between semantically close genres. For example, action and adventure can overlap, while thriller, horror, and crime can share similar plot words.

Precision, recall, and F1 tell slightly different stories. Precision measures how many predicted items of a class are correct. Recall measures how many true items of a class are found. F1 balances the two. In this task, macro recall is important because a model can get good accuracy by predicting common classes but still miss smaller genres. For example, adventure can be confused with action because many films contain both action scenes and travel or quest elements. This is why the report focuses on macro-F1 rather than accuracy alone.

\subsection{Error Sources}
There are four main sources of error. First, genre labels are not always mutually exclusive. A film labelled as thriller may also look like horror or crime from its plot. Second, the Wikipedia genre field is noisy and often compound. Although we use a priority mapping rule, a single-label mapping cannot fully represent multi-genre films. Third, the two datasets have different writing styles. IMDb text is closer to marketing language, while Wikipedia text includes the whole story. Fourth, some genres have fewer samples even after balancing. These factors explain why no model achieves very high scores.

The results also show a useful lesson about deep learning. A more complex input pipeline is not always better. TextCNN tries to learn embeddings and phrase filters from the same medium-sized training data, while TF-IDF MLP starts from a stronger text representation that already highlights important words. This makes TF-IDF MLP more stable for this coursework setting. For future work, pretrained embeddings or larger labelled movie datasets may improve the embedding-based model.

\subsection{Reproducibility}
All output tables are generated from project files. The cleaned datasets are saved in path "data/processed". Dataset statistics are saved in path "outputs/tables/". Model reports and prediction files are saved in path "outputs/results/". The final comparison table is saved as "outputs/results/model\_comparison.csv".

The generated figures are saved in path "outputs/figures/". The deep learning environment uses PyTorch CUDA on the local GPU. Since the scripts fix the random seed, the results should be close when rerun under the same software versions, although small GPU numerical differences may still occur.

\section{Conclusion}
This experiment implements a complete document topic classification system on two movie text datasets. The results show that dataset style is important. Short IMDb summaries and long Wikipedia plots behave differently. Traditional TF-IDF models remain powerful, especially SVM. Neural models can work as well. TextCNN provides a standard deep text classification baseline, and TF-IDF MLP shows that combining feature engineering with neural classification can be effective. However, deep learning is not automatically better and it may need more details. For medium-sized datasets with uneven labels and strong keyword signals, simple traditional methods can still be the most reliable choice.
